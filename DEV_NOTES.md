# Dev notes

Running list of gaps, design tradeoffs, and decisions found while building and testing against a real lab. Not all of these need fixing — some are accepted limitations — but worth tracking so they don't get forgotten.

## Identity / deduplication

- **No-IP devices (e.g. ESXi hosts) can appear as duplicate nodes.** Devices with no CDP/LLDP management address (no serial either, since we never connect to them) have no reliable identity key, so the same physical host discovered from two different neighbors becomes two separate `Device` records. Confirmed happening in real testing — the same-named endpoint host showed up more than once, connected to different switches. Coworker independently flagged this same gap during review (framed as "how do you know two endpoints are actually the same endpoint"). Candidate fix discussed: LLDP's Chassis ID field is often a hardware MAC address, obtainable pre-connect like IP, and could serve as a third identity tier (serial → IP → MAC) — but this would only help for devices that actually speak LLDP and advertise a system-wide (not per-NIC) Chassis ID; devices that don't run LLDP or only speak CDP would still have zero identifying signal, which is a hard ceiling, not a solvable gap. **Deferred post-MVP (2026-09-08)** — explicitly decided not to add this for the MVP.

## Connectivity / credentials

- **Single credential set for the whole traversal.** `discover_topology` takes one username/password/secret and reuses it for every device. Real lab testing showed a handful of devices reject those creds — currently treated the same as unreachable (skipped, left unconfirmed).
- **Arbitrary IP selection when a device has multiple known IPs.** `ip = next(iter(device.ips))` in `discovery.py` picks one from an unordered set — no logic to retry a different known IP if the chosen one fails to connect.
- **Only two exception types caught around `connect()`/`send_command()`.** `NetmikoTimeoutException` and `NetmikoAuthenticationException` are handled; other failure modes (e.g. a command hanging after a successful connection) aren't specifically handled yet.

## MVP status

**MVP feature freeze declared 2026-09-08.** All originally-specified pieces are built: parsers, identity model, connection layer, discovery traversal, graph building, matplotlib preview, draw.io export (with per-end interface labels and confirmed/unconfirmed color coding, added after coworker review), and CLI wiring (`main.py`, `argparse --seed`). `README.md` now documents setup/usage/output. Everything below this point is either an accepted limitation or an explicitly deferred future improvement — no new features planned until after MVP review.

## Rendering limitations

- **matplotlib quick preview doesn't offset parallel edges.** Since the graph is a `MultiGraph`, two separate physical links between the same pair of devices (e.g. two redundant physical links between the same two devices) are stored correctly as two distinct edges, but `nx.draw()` doesn't visually separate them — they'll overlap and look like a single line in the quick preview. Acceptable for a fast sanity-check tool; the draw.io export can do better (e.g. curved/offset lines) since it's the primary output.
- **draw.io export node spacing is not reliably overlap-free for larger topologies.** `export_to_drawio` uses `nx.spring_layout()` scaled by a fixed `CANVAS_SCALE` to place nodes, but `spring_layout` treats nodes as dimensionless points — it has no concept of the fixed `140x60` box size, so it can't guarantee any two boxes won't overlap, especially around densely-connected hub devices (a core switch with many neighbors, for example). Tuning `spring_layout`'s `k`/`iterations` or scaling `CANVAS_SCALE` with node count are heuristic mitigations only, not a real fix. More reliable options: a Graphviz layout with explicit overlap removal (`sfdp`/`neato` with `overlap=false` — requires installing the Graphviz binary, a real added dependency), or relying on draw.io's own built-in auto-layout (Arrange → Layout → Organic/Tree) as the actual overlap-aware arrangement step after import, since draw.io's layout engine does know about box sizes. **Decision (2026-09-01): rely on draw.io's built-in auto-layout rather than building/improving a Python-side layout algorithm.** `export_to_drawio`'s current `spring_layout`-based positions are good enough as a rough starting point; no further code changes planned here. In practice, **Arrange → Layout → Vertical Flow** has worked best (better than Organic/Tree for this topology shape) — this is now documented as a required manual step in `README.md`'s "Cleaning up the layout" section, so users aren't left to discover it themselves.

## Future improvements (out of original scope)

- **EtherChannel/port-channel bundles aren't detected.** CDP/LLDP report per physical member interface, so a multi-link EtherChannel between two devices currently shows up as multiple independent parallel edges (handled correctly, since `MultiGraph` supports this) but with no indication they're actually one logical bundle. Detecting this would need a new parser + an additional command (`show etherchannel summary` or similar) to group member interfaces together. **Deferred post-MVP (2026-09-08).**
